# 数字人（Digital Twin）对话：准备清单与路线选择

> 建档日期：2026-09-22
> 用途：课程「主页最终扩展（5%）」要求个人主页必须连接 Digital Twin 或知识库，或实现一个重要新功能。
> 知识库那一条**已经做完并上线**；这份文档是为了把「数字人」这条更难的路线先想清楚，再决定要不要动手。

---

## 一、先说结论

**数字人对话不是「装个插件」就能做的事。** 它的成本几乎全在三个地方：**实时视频生成**、**语音**、**检索**。其中前两项决定了价格量级。

三条可选路线，按「从省事到硬核」排：

| 路线 | 做法 | 一次对话的大致成本 | 需要什么 | 适合谁 |
| --- | --- | --- | --- | --- |
| **C（推荐起步）** | 文字或语音 + 一张静态头像 | 约 ¥0.01 级（只有 LLM 调用费） | 只要一个 LLM API Key | 想先跑通「回答内容像不像我」 |
| **A** | 直接用商业 SaaS（口型+表情实时生成） | 免费额度内 ¥0，超出约 ¥2.5 / 分钟 | 绑卡 + 订阅 | 要「看起来像真人」，且接受按月付费 |
| **B** | 开源自建（SadTalker / Wav2Lip / MuseTalk） | 模型免费，但**电费和显卡很贵** | **一块 NVIDIA 显卡** | 有显卡、要完全自己掌控 |

**我的建议顺序：先做 C 把「内容」跑通，再决定要不要花钱上 A。** 因为数字人最容易被吐槽的地方不是「脸假」，而是「答得不像本人」——而那是 RAG 的问题，跟视频技术无关。

## 二、路线 A：商业 SaaS

### Tavus（信息最全，数字来自其官方定价页，查询日期 2026-09-22）

| 套餐 | 月费 | 包含分钟数 |
| --- | --- | --- |
| Starter | $22 / 月 | 100 分钟 |
| Builder | $59 / 月 | 500 分钟 |
| Growth | $397 / 月 | 1500 分钟 |

- 超出套餐后约 **$0.35 / 分钟**（Growth 档之后）
- 有 **免费 20 分钟 / 月**，但**需要绑卡**
- **自带 Knowledge Base / RAG 功能**：可以把我的知识库文档直接喂给它，不用自己写检索

**优点**：不用显卡、自带实时口型与表情、自带知识库功能、有免费额度可先试。
**缺点**：按月订阅，超出后按分钟计费，长期用下来不便宜；数据要交给第三方。

### D-ID

- 有 Trial，但**带全屏水印**
- API Key 在 `studio.d-id.com/account-settings`
- **价格页是动态渲染的，抓不到具体数字**——所以我这里不写价格，用之前必须自己去页面确认

### HeyGen

- 有免费额度，但**具体额度未取到**
- 同样是动态页面，价格需要现场确认

> **一项如实说明**：以上 D-ID / HeyGen 的数字我没有核到，不写。真正要下单前必须自己打开定价页确认，不要照着别处的二手数字做预算。

## 三、路线 B：开源自建（需要显卡）

| 项目 | Star | 最近更新 | 许可 | 备注 |
| --- | --- | --- | --- | --- |
| SadTalker | 14.1k | 2024-06-26（**已停更**） | Apache 2.0 | 老牌可商用，但两年没动 |
| Wav2Lip | 13.2k | 2025-06-22 | **无商用许可** | 想商用要走 sync.so |
| MuseTalk | 6.6k | 2025-09-26 | MIT | **需要 NVIDIA GPU**，V100 上可 30fps+ 实时 |
| LivePortrait | — | 2025 年仍更新 | MIT | 仓库已迁移到 KlingAIResearch |

**硬门槛**：这些都需要一块 NVIDIA 显卡。我的机器是 Apple Silicon，**跑不了**，必须租云 GPU（按小时计费）或换机器。

**结论**：路线 B 目前不考虑。不是技术不行，是「为了一个主页扩展去租显卡」性价比太低。

## 四、路线 C：文字/语音 + 静态头像（推荐起步）

### 做法

```
访客提问
  → 后端把问题转成向量，从我的知识库里检索最相关的几段
  → 拼成提示词（问题 + 检索到的资料 + 「按刘博康的口吻回答」）
  → 调用 LLM 生成回答
  → 前端显示在气泡里 + 一张静态头像
```

### 用哪个模型

DeepSeek 官方价（查询日期 2026-09-22）：

| 项目 | 数值 |
| --- | --- |
| 模型 | `deepseek-flash` |
| 输入 | $0.15 / 百万 token |
| 输出 | $0.6 / 百万 token |
| 上下文 | 1M token |

**换算一下**：一次几分钟的对话，输入加输出撑死几千 token，成本在 **¥0.01 量级**。这是三条路线里唯一「可以随便试」的价格。

### RAG 的最小做法（不用向量数据库）

1. 把知识库的 Markdown 按标题 / 段落切成 **200–500 字**的小块，每块带上来源文件名
2. 用 embedding 模型给每块算向量，存成一个本地文件（几千块用不上数据库）
3. 访客提问时，算问题向量，找出最相关的 3–5 块
4. 把这几块拼进提示词，让模型**只依据这些资料回答**，并注明出处

**这一步不需要 GPU，也不需要向量数据库**——文档量在几千块以内，用本地文件做余弦相似度就够了。

## 五、准备清单

### 一、必须先有（没有就动不了）

| # | 准备项 | 现在的状态 |
| --- | --- | --- |
| 1 | **决定走哪条路线** | ❌ 待定（本文档就是给他拍板用的） |
| 2 | **决定用什么模型 API** | ❌ 待定（DeepSeek 最省，但要确认是否愿意开 key） |
| 3 | **把知识库语料准备好** | ✅ **已经有了**——`src/content/notes/*.md` 共 10 篇，另外主页的项目详情本身也是语料 |
| 4 | **把 API Key 放在不能被抓到的地方** | ❌ 待做——**关键难点**，见下 |
| 5 | **确认「能花多少钱」** | ❌ 待定（路线 C 可以忽略，路线 A 要按月预算） |

> **第 4 项是真正的技术难点。** 主页是纯静态站点（GitHub Pages 没有后端），访问者打开网页就能看到前端代码。**如果 Key 写在前端，等于把 Key 公开发到互联网上**，几分钟内就会被爬走刷爆。
>
> 三个解法，按推荐顺序：
> 1. **加一个极小的中间层**（Cloudflare Workers / Vercel 这类免费额度够用的 Serverless 函数），Key 存在服务端环境变量里，前端只调这个中间层。
> 2. **不做实时对话**，改成「预先生成一批问答结果」的静态页面——零风险，但只能回答预设问题。
> 3. **只在本地演示**（截图 / 录屏给评审看），不把接口发到线上。

### 二、有了更好（能明显提升效果）

| # | 准备项 | 说明 |
| --- | --- | --- |
| 6 | **我的语料专属化** | 光有技术笔记不够；要让它「像我」，得有自我介绍、学习方式、兴趣爱好这类**第一人称文本**。可以从主页的「关于」页直接转 |

## 六、风险（必须提前想清楚）

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| **密钥泄露** | 前端暴露 Key 会被刷爆；账单可能挂到几十上百美元 | 用 Serverless 中间层，并给 Key 设额度上限 |
| **成本失控** | 被人恶意循环调用 | 加限流（同一 IP 每天 N 次）、设月度上限 |
| **隐私与肖像权** | 数字形象涉及真人肖像；语料可能含他人信息 | 只用本人素材；语料先脱敏 |
| **答错话** | 模型可能编造与我经历不符的内容 | 提示词里写死「只依据资料回答，查不到就说不知道」，并注明出处 |
| **平台限制** | GitHub Pages **不能跑后端** | 用 Serverless 中间层，或改成静态问答 |
| **延迟** | 检索 + 生成 + 语音合成串起来会慢 | 先做纯文字，能接受再加语音 |

## 七、下一步建议

**最小可行版本（半天到一天的工作量）：**

1. 把「关于」页和我写的 10 篇笔记作为语料，切块 + 算向量，落成一个本地文件
2. 写一个 `/ask` 的 Serverless 函数（Key 放在环境变量里）
3. 主页加一个「和我聊聊」的入口，先做**纯文字对话 + 静态头像**
4. 用准备好的 10–15 个问题测一遍，把答得不好的记下来，回头改语料和提示词

**先不做的**：视频、语音、实时口型。等文字版真的答得像我了，再决定要不要为「脸」花钱。
