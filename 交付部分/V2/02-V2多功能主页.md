## 十、联系表单第三方后端选型（Formspree → FormSubmit）

线上是纯静态站点，自建 Node 后端无法在 GitHub Pages 运行，故联系表单必须依赖第三方表单服务。选型过程记录如下：

1. **尝试 Formspree（失败）**
   - 注册后卡在邮箱验证：点邮件里的验证链接会不断新开 Formspree 页面、**陷入死循环**（官方文档「Couldn't verify email」描述的正是此问题）。
   - 排查确认非网络问题（`formspree.io` 直连 HTTP 200）。用户决定放弃 Formspree。

2. **备选排查**
   - **Web3Forms**：该网络下被拦（`web3forms.com` / `api.web3forms.com` 直连 **403**，带浏览器 UA 仍 403）→ 不可用。
   - **FormSubmit（`formsubmit.co`）**：直连 HTTP 200、AJAX 接口可用 → **采用**。

3. **FormSubmit 接入（最终方案）**
   - **最大优点**：无需注册、无需邮箱验证循环；只需向「你的邮箱」的 AJAX 端点提交，**首次提交触发一封激活邮件，点一次「Activate Form」即可永久启用**。
   - 前端 `ContactView.vue`：`FORM_ENDPOINT = import.meta.env.VITE_FORM_ENDPOINT || 'https://formsubmit.co/ajax/carrotsoup@qq.com'`；JSON 提交，约定字段 `_subject`（主题）、`_replyto`（回复地址）、`_captcha: 'false'`（静默 AJAX）、`_template: 'table'`。
   - 响应判定：`data.success === true || 'true'` → 成功态。
   - 用户已点击激活邮件，接口实测返回 `{"success":"true","message":"The form was submitted successfully."}`。

4. **线上端到端验收（CDP 实测）**
   - ⚠️ 踩坑：hash 路由跳转（`#/`→`#/contact`）**不会重载文档**，浏览器仍用旧缓存 bundle（Formspree 版），报「Form not found」。→ 用**带时间戳整页重载**（`?t=xxx#/contact`）后加载新 bundle（`index-gyERFV-P.js`）。
   - 结果：填表 → 提交 → 页面显示「**✅ 已收到你的留言！我会尽快回复。**」，QQ 邮箱收到留言邮件。
