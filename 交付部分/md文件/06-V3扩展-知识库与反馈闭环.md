## 二、A1：知识库从「占位」变「真实内容」

### 2.1 改之前的问题

| 问题 | 说明 |
|------|------|
| 内容是假的 | `site.js` 里 3 条 `note-1/2/3` 示例笔记，页面还挂着「建设中」横幅 |
| 加一篇要改代码 | 笔记是 JS 数组里的字符串，改内容 = 改代码 |
| 不能搜索 | 只有标签筛选 |
| 链接不可分享 | 打开某篇笔记没法把地址发给别人 |

### 2.2 改法：内容与代码分离

```
src/content/notes/*.md     ← 每篇笔记一个 Markdown 文件（带 frontmatter）
src/data/notes.js          ← 加载 / 解析 / 检索（唯一的一块代码）
src/views/KnowledgeView.vue← 只管展示
```

一篇笔记长这样：

```markdown
---
title: Vite 构建与 GitHub Pages 部署：一条命令背后的四件事
date: 2026-09-17
tags: [前端, 部署, Vite]
summary: npm run build 到底做了什么；为什么部署到 /homepage/ 子路径要改 base。
---

正文……
```

加载靠 Vite 的 `import.meta.glob`：

```js
const modules = import.meta.glob('../content/notes/*.md', {
  query: '?raw',      // 拿到原始文本，而不是当成模块执行
  import: 'default',
  eager: true,        // 构建时一次性读入
})
```

**关键收益**：新增笔记 = 往 `src/content/notes/` 丢一个 `.md` 文件，**不用改任何代码**。
这正是课程「publishing a working project and connecting it with appropriate supporting services」里
「内容可持续补充」的落点。

### 2.4 知识库页面重写

新增/改进：

- **关键词搜索**（标题 + 摘要 + 正文 + 标签一起搜）
- **标签筛选**（按出现频次排序，当前选中态用 `aria-pressed`）
- **结果计数** + **空状态**（搜不到时给一句「换个词试试」和「查看全部」按钮）

- 每篇显示**阅读时长**（按中文 350 字/分钟估算）
- **移除「建设中」横幅**——内容真实了，就不该再挂占位提示

## 三、A2：内容反馈闭环

### 3.1 为什么做这个

课程明确要求「Collecting feedback, evaluating results, and making evidence-based improvements」。
原来只有「联系我」页面有一个通用留言框，访客看完一篇笔记想吐槽，得跳到另一个页面——**反馈入口离内容太远，收集率必然低**。

### 3.2 组件设计：三步，尽量少打断

新增 `src/components/FeedbackWidget.vue`，贴在**首页结尾、每个项目详情页、每篇笔记末尾**。

```
第 1 步  这部分内容对你有用吗？     [👍 有用] [🤔 还需改进]
   ↓ 点任一
第 2 步  你觉得「有用」——能再说一句为什么吗？（选填）
          [文本框]                              [提交反馈] [跳过]
   ↓ 提交
第 3 步  ✅ 谢谢！你的反馈已收到（有用）。
         我会把它记录进《用户反馈与改进记录》，并据此改进内容。
```

几个刻意的取舍：

| 决定 | 理由 |
|------|------|
| 先给两个按钮，再问原因 | 一键就能表达态度，门槛低；愿意多说的再展开 |
| 留言**选填**，「跳过」也能提交 | 强制填字会让人直接关掉 |
| 反馈后记在本机 `localStorage` | 同一个人不重复被问（按「页面 + 笔记 id」分别记） |
| 提交内容带 `page` / `item` / `url` | 收到邮件时知道是哪一页、哪篇笔记的反馈 |

### 3.3 顺手消掉的重复

原来 `ContactView.vue` 里写死了 FormSubmit 的地址和约定字段。新增反馈组件如果照抄一遍，
以后换后端要改两个地方。于是抽出 `src/data/feedback.js`：

```js
export const FORM_ENDPOINT =
  import.meta.env.VITE_FORM_ENDPOINT || 'https://formsubmit.co/ajax/carrotsoup@qq.com'

export async function sendToFormSubmit(payload) { /* 统一提交 + 统一判定成功 */ }
```

`ContactView.vue` 一并改为复用，行为不变。

### 3.4 反馈记录模板

新增 `交付部分/md文件/05-用户反馈与改进记录.md`，含七个部分：收集渠道 / 原始记录表 / 汇总诊断 /
优先级与改进计划 / **据反馈所做的实际改动** / 证据清单 / 总结。

> ⚠️ 该文件目前是**空模板**。课程禁止编造真实用户验证，所以表格留白，
> 等真实收集到反馈后再填——这一环只能靠本人去找人试用。

## 四、A3：最小自动化测试

### 4.1 为什么加

课程要求原型带「basic testing」。原来 `package.json` 里连 `test` 脚本都没有，
所有验收都靠手点，改一行不知道有没有碰坏别处。

### 4.2 加了什么

`vitest` + `@vue/test-utils` + `jsdom`——**只进 devDependencies**，不打包进产物。

```json
"scripts": {
  "test": "vitest run",
  "test:watch": "vitest"
}
```

### 4.3 5 个测试文件 / 31 条断言

| 文件 | 测什么 |
|------|--------|
| `notes.spec.js` | 内容管线：能载到笔记、frontmatter 的 tags 解析成数组、按日期倒序、标签去重、关键词与标签筛选是「同时满足」、搜不到返回空数组 |
| `site.spec.js` | 站点数据：项目 id 唯一且不含空格、每个项目都有正文、详情图都有 `alt`、外链都是 https |
| `router.spec.js` | 路由表：五个页面都在、`/project/:id` 能传出 id、每个路径都能解析出组件、未知地址被兜底规则接住 |
| `feedback.spec.js` | 反馈出口：提交到正确端点、自动带 `_captcha:'false'`、成功/失败/非 JSON 四种返回值都能正确判定 |
| `feedback-widget.spec.js` | 反馈组件：初次询问、选态度后才出输入框、提交后显示感谢、发出的字段完整、本机记过不再追问、接口失败与网络异常都不假装成功 |

命令与结果：

```

      Tests  31 passed (31)
```

> 这一批测试当场就起了作用：写 `site.spec.js` 时我以为 `site` 有 `role` 字段，
> 跑测试才发现在 `site.js` 里实际叫 `tagline`——测试帮我纠正了对自家代码的错误记忆。

### 5.3 一个调试插曲（记下来备查）

用脚本给页面截图时，连续 4 次 `Page.captureScreenshot` 超时，且截出来的是**上一次的旧图**，
一度以为知识库页面白屏了。实际原因是：**浏览器后台标签页不产生动画帧**，截图会一直等不到。
把页面切到前台（重新打开该地址）后一次就成功；另外查询 DOM 也证实内容一直都在
（`#app` 内有 8745 字符）。

## 七、还没做的（诚实记录）

第一批只解决了「换分三件套」。以下已定位但**本轮未动**：

- **B1 每页独立标题**（WCAG 2.4.2）：全站标题仍是同一个。
- **B2 SEO / 社交元信息**：`index.html` 缺 `og:` / `twitter:` / `canonical`，也没有 `robots.txt`、`sitemap.xml`。
- **B3 键盘可达与焦点**：全站没有 `:focus-visible` 样式，也没有「跳到主内容」链接（WCAG 2.4.1 / 2.4.7）。
- **B4 404 页面**：未知地址目前静默跳回首页（NN/g #9）。
- **B5 性能与 CLS**：所有 `<img>` 缺 `width`/`height`，是唯一的 Core Web Vitals 风险点。
- **C4 对比度实测**：浅色主题下绿色/石板蓝小字需用工具实测是否达 4.5:1。
- **反馈数据仍是空的**：`05-用户反馈与改进记录.md` 需要真实收集后才能填。

以上构成第二批、第三批的输入，见 `docs/优化方案-课程差距与权威标准.md`。
