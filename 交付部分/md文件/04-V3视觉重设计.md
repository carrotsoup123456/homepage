## 一、设计参考与合规原则

### 1.1 参考来源

用户提供了 4 张参考图（`uploads/ses_f9505a767ffewYuN3QWGmupKUi/`）：

| 参考 | 学习点 |
|------|--------|
| `image.png`（视差示意） | 分层视差滚动的空间纵深感 |
| `image-2.png`（Bayshore） | 画廊式艺术感：暖色底、细边框「画框」、大留白、衬线标题 |

| `image-4.png`（Amperos） | 个人主页结构：大标题 Hero + 人像、徽标条、左右交替特性行 |

### 1.2 合规原则（重要）

- **学习「思想 / 模式 / 布局」不侵权**，**1:1 复刻具体表达会侵权**。
- 因此 V3 **不直接使用参考图的任何图片素材**，而是提取其设计语言（配色关系、排版结构、构图方式），并用 **DeepWorks 生图产出原创背景素材**，从源头规避版权风险。
- 素材版权：本项目背景图为 AI 原创生成；头像与项目截图为本人所有。

### 3.2 排版与质感

- **标题**：衬线栈（Iowan Old Style / Palatino / Songti SC）
- **正文**：无衬线栈（PingFang SC）
- **兼容性**：**保留 V2 全部 CSS 变量名**并新增令牌，使 About / Knowledge / Contact / ProjectDetail 等旧视图无需改动即可继承 V3 配色。

### 3.3 深色主题对比度修复

- 问题：深色主题主色偏亮（`#a9c6da`），若沿用白色文字会出现低对比度。
- 修复：新增 `--color-on-primary` 令牌，主色填充元素（知识库筛选项、建设中徽标、返回顶部按钮）改为引用该令牌；头像描边由硬编码 `#fff` 改为 `var(--color-surface-2)`。

## 五、动态效果实现（5 项）

在 V3 既有动态（Hero 分层视差、悬浮标签 floaty、滚动提示 cue、技能跑马灯、全站 `v-reveal`、返回顶部、主题切换过渡）之上，新增 5 项动态元素。**实现约定：纯 CSS + 少量原生 JS，不新增任何依赖，双主题适配，并遵守 `prefers-reduced-motion`。**

| # | 元素 | 实现位置 | 关键实现 |
|---|------|----------|----------|
| 1 | **首屏进场编排** | `style.css` `@keyframes heroEnter` / `cueEnter` | 按 0.05→0.9s 依次延迟：kicker(0.05s) → title(0.16s) → portrait(0.26s) → tagline(0.3s) → actions(0.44s) → scroll-cue(0.9s)，`forwards` 定格，cue 保留 `translate(-50%,…)` |
| 2 | **森林萤火虫** | Hero 内 `.fireflies` 层（22 个 `span`） | CSS 随机参数：尺寸 4–9px、`--dur` 7–15s、`--delay` 0–6s、位移 `--dx/--dy`、峰值透明度 `--peak`；白色核心 + 绿色光晕 `radial-gradient` + `box-shadow`；`@keyframes firefly` 含 12%–45% 亮度平台期；`pointer-events:none` + `aria-hidden` |
| 3 | **鼠标跟随柔光** | Hero `.hero-glow` 层 | `radial-gradient(380px circle at var(--mx,50%) var(--my,40%), rgba(198,255,212,.24), .08 42%, 0 72%)`；`@mousemove` + `requestAnimationFrame` 节流写入 `--mx/--my`；`.hero-v3:hover .hero-glow{opacity:1}` |
| 4 | **统计数字滚动增长** | `HomeView.vue`（`statValues`） | 数值化 2 / 10 / 3 / 2026；`IntersectionObserver`(threshold 0.4) 触发 + rAF cubic ease 递增（1500ms） |
| 5 | **区块交错滑入** | `directives/reveal.js` 新增 `revealStagger` | 观察容器，给子项加 `.reveal` + `i*step` 的 `transitionDelay`（`step` 默认 90ms）；注册为 `v-reveal-stagger`，用于 `.timeline`（两处）、`.stat-grid`、`.feature-list`（`{step:70}`） |

**层级修正**：新增 `.hero-inner{position:relative;z-index:1}`、`.scroll-cue{z-index:2}`，保证内容与提示在粒子/柔光层之上。

**无障碍降级（`prefers-reduced-motion: reduce`）**：

- `animation:none` 覆盖 Hero 进场类、`.scroll-cue`、`.fireflies span`；
- `.fireflies, .hero-glow { display: none }`（彻底不渲染）；
- 统计数字初值即终值（不滚动）；`.reveal` 全部 `opacity:1`。

**验证（CDP 自动化，可见标签页）**：萤火虫 22 个且 `animationName: firefly`，画面中清晰可见绿色光点；`.hero-title` = `heroEnter`、`.scroll-cue` = `cueEnter`；滚动后统计终值 `2 / 10 / 3 / 2026`；timeline 5 项 / feature-list 6 项 / stat-grid 4 项均带 `.reveal`；`Input.dispatchMouseEvent` 后 `--mx=70.18%`、`--my=42.98%`、`.hero-glow` opacity=1；reduced-motion 下上述动态全部关闭。
截图证据见 `outputs/V3-动态效果验证/`（10 张，含线上复验）。

## 七、调试过程中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 浅色整页截图出现「画面平铺重复」 | `captureBeyondViewport` 与 `will-change` / `sticky` / 背景合成的 Chrome 合成 bug | 冻结 vh 高度 + 重建全新渲染目标后截图 |
| 2 | CDP 渲染进程卡死（截图超时） | 旧渲染进程被反复整页截图拖垮 | 关闭旧目标、通过浏览器扩展新建标签页 |
| 3 | 深色主题主色填充文字对比度低 | 深色主色偏亮 + 硬编码白色文字 | 新增 `--color-on-primary` 令牌 |
| 4 | 生图自带水印 | 生图服务默认叠加水印 | 裁剪右下角后导出 JPEG |
| 5 | 页面级 WebSocket 调试地址恒返回 500 | 该 Electron/Chrome 构建不支持 page 级 ws | 改用浏览器级 `webSocketDebuggerUrl` + `Target.attachToTarget({flatten:true})` + `sessionId` |
| 6 | `Target.createTarget` 返回 `Not supported`，空白 target 是僵尸 | 构建限制 | 通过 DeepWorks 扩展 `openwork-browser` / `open_url` 新建并激活标签页 |
| 7 | 后台 / 遮挡标签页截图挂起（`currentTime` 恒 0、`captureScreenshot` 超时） | 只有当前可见标签页才产生动画帧 | 用 `open_url` 打开页面保证标签页可见；不在截图时全局暂停动画 |
| 8 | 整页截图 Hero 被 `100vh` 撑满，形成「整页」假象 | Hero `min-height:100vh` | 截图前将 `.hero-v3` 的 `minHeight` 钉为视口高（如 900px） |
