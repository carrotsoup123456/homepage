> 时间：2026-09-22

> 相关提交：站点产物 `gh-pages`（`c17f89c` → `b48816d`）；源码进 `main`。

## 一、这一批要解决的问题

前一批（07）把项目库和「关于」页补厚了，但对照一遍权威标准（WCAG 可访问性 + 常规 SEO 惯例），仍有一批"一眼就能看出没打磨"的地方：

| # | 问题 | 表现 |
|---|------|------|
| 1 | 所有页面共用一个浏览器标题 | 切到"关于/知识库/联系"，标签页文字始终是 `刘博康 – 个人主页`，浏览器历史里一片重复 |
| 2 | 没有分享信息与搜索引擎信息 | 链接发给别人，社交平台抓不到标题和摘要；搜索引擎不知道哪个地址是"正式地址" |
| 3 | 没有 `robots.txt` / `sitemap.xml` | 搜索引擎只能靠猜 |
| 4 | 键盘基本不可用 | 全站几乎没有焦点样式，没有"跳到主要内容"，导航也没有"当前在哪一栏"的标记 |
| 5 | 没有 404 页 | 网址打错会被**静默跳回首页**，用户不知道自己点错了 |
| 6 | 图片没写尺寸 | 图一张张加载时，下面的内容被反复往下顶（CLS，布局跳动） |

这六件事都不影响"功能能不能用"，但都会影响"看起来像不像成品"，也都属于课程所要求的 evidence-based improvements。

## 二、逐项做法

### 2.1 每页独立标题 + 分享信息（B1 / B2）

新增 `src/data/meta.js`，把"页面元信息"收进一个地方：

- 站点常量：站名、正式地址、默认标题与默认描述；
- `urlFor(path)`：拼出当前页的正式地址（`canonical`）；
- `setPageMeta({ title, desc, path })`：把标题、描述、`canonical`、`og:*`、`twitter:*` 写进 `<head>`；**同一个标签只更新、不重复插入**（幂等）。

路由表里每一页挂上 `meta.title` / `meta.desc`；`App.vue` 里用：

```js
watch(() => route.fullPath, applyMeta, { immediate: true })
```

为什么用 `watch` 而不是 `router.afterEach`：**测试里会自建 router 实例**，`afterEach` 不一定被注册上，用 `watch` 跟着当前路由走更稳。`immediate: true` 保证首次打开就生效。

笔记页与项目详情页这类"内容决定标题"的页面，由页面自己用 `{ flush: 'post' }` 覆盖成更具体的标题（例如「回测数字的陷阱：112.74% 应该怎么读 · 知识库 · 刘博康」）。

另外 `index.html` 里补上 `author` 与首屏默认的 `og:`，并顺手修正头像的尺寸标注（实际是 1280×1920）。

搜索引擎文件：`public/robots.txt` 允许抓取并指向 `sitemap.xml`；`sitemap.xml` 只登记站点入口一条——因为本站是 hash 路由，**所有页面在服务器看来都只有一个地址**，登记一堆 `#/...` 反而是错的。

### 2.2 键盘可用（B3）

| 改动 | 说明 |
|------|------|
| 全局 `:focus-visible` | 之前只有"关于"页的技能卡有焦点样式，其余全是默认（或没有）。现在统一给按钮、链接、输入框画可见焦点。 |
| 「跳到主要内容」 | 页首加 `.skip-link`，平时藏起来，键盘第一次 Tab 就出现。注意：**不能直接跳 `#main`**——hash 路由下那等于触发一次路由跳转，所以改成拦截默认行为 + 把焦点移进主内容区（`main` 加 `tabindex="-1"` 才允许被程序聚焦）。 |
| 当前栏目标记 | 导航链接按当前路由加 `aria-current="page"`，让读屏软件和键盘用户知道自己在哪。 |
| 导航按钮语义 | 移动端菜单按钮补上 `type="button"` 与 `aria-expanded` / `aria-controls`；按 Esc 关闭菜单并把焦点还给按钮；切换路由后自动收起。 |
| 灯箱（大图） | 打开时 `role="dialog"` + `aria-modal="true"`，焦点移到关闭按钮；**按 Esc 关闭并把焦点还回原来那张图**，焦点不会丢到页面外面。 |
| 装饰性 emoji | 包上 `<span aria-hidden="true">`，避免读屏软件把"👍"读成一串字符。 |

### 2.3 真 404（B4）

原来的兜底路由是 `redirect: '/'`——用户点错链接会被悄悄送回首页，以为一切正常。现在：

- 兜底路由渲染 `NotFoundView`：「这个页面不存在」+ **回显错误地址**（让人知道是哪个链接坏了）+ 返回首页/看项目两个出口；
- 额外加 `public/404.html`：如果是**把网址本身打错**（连应用都没启动），由它兜住，内容同样是「页面不存在」并引导回首页，附 `meta refresh` 与 `noscript` 双保险。

### 2.4 图片防跳动（B5）

- 新增 `scripts/gen-image-sizes.mjs`：直接读文件头拿真实像素（PNG 读 IHDR、JPEG 读 SOF、SVG 读 viewBox），生成 `src/data/image-sizes.js`，**零依赖**，换图后跑一次 `npm run gen:images` 即可。
- 全站 `<img>` 绑定 `width` / `height`（首页 hero、经历图、项目详情图、头像），浏览器据此**先留出位置**。
- CSS 补 `img { max-width: 100%; height: auto }`——`height: auto` **不能省**，它让"留位用的原始比例"与"窄屏下的实际宽度"兼容，否则手机上会被压扁。

### 2.5 顺带修的

- `src/style.css` 里重复定义的 `.sr-only` 合并成一份。

## 五、一次"看起来像线上崩了"的假警报

线上复验时出现：**地址变了、标题也变，但正文一直停在首页**。看着像线上路由彻底坏了。

排查过程：

| 步骤 | 观察 |
|------|------|
| 1 | 直接问页面：`requestAnimationFrame` 一秒内触发 **0 次** |
| 2 | `document.visibilityState` = **`hidden`**（标签页在后台） |
| 3 | 路由容器 class 停在 `page-leave-active`，没进下一步 |

结论：路由视图外面套着 `<Transition mode="out-in">`（旧的先淡出、新的再进来）。这个流程**依赖浏览器产生动画帧**推进；标签页在后台时浏览器一帧都不产生，动画停在半路，新页面就永远挂不上来。

这是**测试环境（后台标签页）的限制，不是线上缺陷**——真实用户看着窗口时有帧，0.25 秒就切完（本地 dev 实测最长 1.3–2.0 秒也会自行完成）。把"取帧"临时换成"定时器"再跑一遍，线上 7 条路由全部正常，据此确认线上无恙。

> 教训：验证页面状态既不能"打开就开始读"，也不能用固定等待。**要么轮询到状态真正落定，要么先确认标签页确实在前台。**

## 六、这一批学到的事

1. **"测试通过"不等于"验证到位"。** 一条断言可以既写出来、又永远为真。反向验证（故意改坏看它变不变红）是唯一能把这种断言揪出来的手段；而且光"改坏一处变红"还不够——要**改坏到"这个问题真的发生"的样子**（这次是把路由改回重定向，而不是改名字）。
2. **一个"看起来像崩了"的现象，先别急着改代码。** 先把观测手段本身是否可靠查清楚。如果当时直接去"修"过渡动画，就等于为一个不存在的问题动了线上代码。
3. **"清理工作目录"和"删除版本库元数据"是两件完全不同量级的事。** 这次为了重新同步部署目录执行了清空操作，把里面的 `.git` 一起删了；靠远端 `gh-pages` 完好副本 fetch 回来做基准、再在其上提交推送（**快进、未强推**）才恢复，远端提交记录一条没丢。**带 `.git` 的目录不能无脑清空。**
4. **改文件和改引用必须成对做**（上一批的教训），这一批补的图片尺寸表同理：换图要重新生成尺寸表，否则断言会拦住你——这正是它该干的活。
