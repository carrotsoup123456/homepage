# 07 项目库扩充与「关于」页改造

> 时间：2026-09-22
> 本批次目标：把散落在其他工作区里的**真实项目**全部补进个人主页，并让「关于」页从"空洞"变成"能看出这个人做过什么"。
> 相关提交：本地 `main`（gh-pages 部署提交另记）

---

## 一、这一批要解决的问题

前一批（06）已经做完知识库与反馈闭环，但暴露出两个新问题：

1. **主页上的项目只有 2 个**（Carbon Brain + 股票量化），而实际上我一共做过 6 个成规模的项目——其中还有一个是**能双击运行的完整模拟游戏**。主页完全没有体现。
2. **「关于」页太空**：除了头像和一行简介就只剩 4 个技能标签。而且这 4 个标签**悬停时有变色动画，看着像能点，点了却什么都没有**——这是最糟的体验：给了期待又不兑现。

本批次就是修这两件事。

## 二、盘点：其他工作区里到底有什么

动手之前先做盘点，把「有真实产出」和「只是文件夹」分开。这一步很关键——**不能凭印象往简历上写项目**。

| 工作区 | 真实产出 | 是否上主页 |
| --- | --- | --- |
| 设身处地 | 《为官一方》古风县令治理模拟游戏（立项书 + 可玩原型 + macOS 应用 + DMG） | ✅ 上，且放在第一位 |
| stock | A 股机器学习量化流程（28 因子、双模型线、回测面板） | ✅ 上（口径改严谨） |
| carbon brain | DAC 材料饱和度预测（团队项目，我任组长） | ✅ 上（口径改严谨） |
| TO-DO Panel | 二改开源桌面面板（加写入通道 + 新组件） | ✅ 上，明确标注上游 |
| 默认工作区 | Claude Code 桌面版二次开发 + ccswitch 额度切换 | ✅ 上两个（其中一个明确标注上游） |
| 邮件处理 | 只有脚手架，`inbox/outbox/previews` 全空 | ❌ 不上（没有产出就不写） |

**盘点得出的第一条结论：邮件处理这个工作区不能写。** 它只有配置文件和空目录，没有任何可展示的内容。这一点如果靠印象写，很容易变成"编"。

## 三、口径修正：把话说严谨（本次最重要的部分）

盘点过程中发现两处**表述不严谨**的地方，都做了修正。这不是文字游戏——它们直接决定了这些内容在追问下能不能站住。

### 3.1 股票量化的 112.74%

**原来的写法**：只写了「总收益 112.74%」。

**问题**：这个数字是**只在界面截图里留存**的，仓库里没有落盘成可复现的结果文件；而且它不是文档里主推的那个模型的成绩。

**改成**：补全口径表——模型是 **LightGBM 回归（调参版本）**、选股 50 只、每 5 个交易日调仓、区间 2025-01-01 至 2026-08-14、基准 46.57%、超额 66.17%、最大回撤 -10.02%；并明确说明这**不是**分类版本的成绩。

**额外补上**：同一个项目里那个**可复现**的传统规则策略，区间收益 16.85%、同期基准 44.93%、**超额 -28.08%**（跑输大盘）。这个"不好看"的数字反而更有信息量，也更能说明我理解自己项目的真实情况。

### 3.2 Carbon Brain 的模型效果

**原来的写法**：「使用机器学习预测饱和度，并让装置自动切换」——读起来像已经做成了。

**问题**：实际上饱和度模型用**按日期切分**的测试集评估时 **R² 为负（-3.07）**，而依赖的突破时间预测模型**从未训练成功**，所以"自动切换"目前还停留在设计与阈值阶段。

**改成**：把「已经做到的」和「还没做到的」分成两块列清楚，并解释 R² 为负的含义——**不是"效果一般"，而是模型在当前数据条件下不具备预测能力**。

**还加了一节「我做错的地方」**：我一开始把"物理换算链路跑通"和"模型可用"当成一件事。链路跑通只证明流程没算错，不证明模型能预测——这两件事必须分开验收。

### 3.3 二次开发项目的边界

TO-DO Panel 和 Claude Code 桌面版这两个项目，上游都是别人的作品。所以：

- **项目标题里就写明**：「上游：xiaopu-ai/TO-DO Panel」「上游为第三方应用」
- **正文第一段先说清楚边界**，再讲我做了什么
- **`role` 字段统一写成「本地二次开发」**，不写「独立开发」

并且给测试加了一条断言，**强制检查**这两个项目必须同时出现「上游/开源/第三方/MIT」和「不主张原创/非原创」两类表述——防止以后改文案时不小心把边界抹掉。

## 四、「关于」页改造

### 4.1 技能标签：从"假可点"变成"真可点"

原实现是一个 `<span>`，有 hover 动画但没有行为。改成 `<button>`：

- 点击展开一张详情卡片，里面写**我拿它具体做过什么**（4 条实际例子）+ **可以在哪些项目里看到**（证据链接）
- 同一时间只展开一张，避免页面被撑长
- 补上键盘可达：`aria-expanded` 状态 + `:focus-visible` 可见描边（原先全站没有焦点样式）
- 展开后右上角的「＋」旋转 45° 变成「×」，给一个明确的视觉反馈

### 4.2 页面从"两段"变"六段"

原来只有「专业技能」+「联系我」，现在补齐：

| 区块 | 作用 |
| --- | --- |
| 自我介绍（加一句"我最感兴趣的是什么"） | 补上"动机"，不只是罗列 |
| **现在在做什么**（3 张卡） | 让访客知道这是活的，不是静态简历 |
| 专业技能（可展开） | 从"我会 Python"变成"我用 Python 做过什么" |
| **我做过的东西**（6 个项目索引） | 直接跳详情页；并注明其中两个是二次开发 |
| **我的工作方式**（4 条原则） | 每条都是踩坑后总结的，比"吃苦耐劳"有信息量 |
| 教育经历 | 补齐时间线 |

### 4.3 顺带修的

- 头像 `<img>` 补上 `width="120" height="120"`（CLS 治理的第一步）
- 联系链接加 `rel="noopener"`
- 移除了一个死掉的 CSS 过渡类（原来用的 `<Transition>` 包 `v-for`，是无效用法，已改回 `v-show`）

## 七、新增的测试断言（防回归）

除了原来的站点数据检查，本次加了三条**有实际约束力**的断言：

1. **项目字段契约**：每个项目必须有 `icon / short / desc / tech / role / highlights / images`，且 `highlights` 非空——防止新加项目时漏字段导致页面渲染报错。
2. **二次开发必须注明上游**：`todo-panel` 与 `claude-code-custom` 的文案里必须同时出现上游来源和不主张原创的声明。
3. **图片路径必须带 base 前缀**：检查每个 `img.src` 以 `/` 开头且是图片后缀——因为 GitHub Pages 部署在子路径下，漏掉前缀就会 404（这个坑已经在 V2 踩过一次）。

## 八、这一批学到的事

1. **盘点比写作更重要。** 花时间搞清楚"工作区里到底有没有产出"，比急着往主页堆内容有价值得多——它直接拦住了一个不该写的项目（邮件处理）。
2. **数字必须带口径。** 112.74% 和 "R² 为负" 都是我的真实数据，但只有后者写清楚了才知道前者为什么不能随便说。
3. **不要给别人留下"这是你的作品"的错觉。** 二次开发是正当的，但表述必须让人一眼看出上游是谁。
4. **"看着能点但点不动"比"不能点"更糟。** 这是用户视角的问题，不是技术问题——修它的成本很小，但体验差别很大。
