## 二、背景（来自课件要点）

- 课程：Project-Based CST&AI Foundations（天津大学深圳学院，Fall 2026，3 学分）。
- Vibe Coding 占 20%：个人主页（Phase 1–4）10% + 主页最终扩展 5% + 独立小项目 5%。

- 关键里程碑（供参考，本计划不含时间）：Vibe Coding 原型评审、项目提案与 MVP 规格、可运行 MVP 评审、用户反馈评审、Beta 版评审、Demo Day、最终复盘归档。

## 三、我的方案（V1 步骤计划）

将 V1 定义为「第一个可运行、可访问、可展示的完整主页版本」，拆分为 7 个阶段：

1. **准备与环境**：技术选型、Git 仓库、AI 编码环境、部署目标。
2. **需求与定义**：主页定位、内容模块、用户画像、MVP 需求清单、V1 范围控制。
3. **原型设计**：信息架构、视觉方向、交互流程、MVP 规格确认。
4. **实现与迭代**：搭建骨架、逐模块实现、AI 辅助编码（记录 prompt）、持续 Git 提交、迭代打磨、响应式。
5. **测试与用户验证**：功能自测、兼容性/性能、真实用户试用、反馈报告。
6. **复盘与归档**：AI 协作记录、过程证据、说明文档、归档提交。

> **说明（已按课件核实修正）**：Vibe Coding 主页部分的评分属于「Phase 1–4」，对应主题是「从想法到可运行的原型」，评审节点是 **Vibe Coding Prototype Review（2026-09-29）**，评的是「原型」。课件对证据的措辞是「**可运行 或 可公开访问**（runnable OR publicly accessible）」——本地可运行即满足，**发布 / 部署并非 Phase 1–4 的硬性要求**。「发布 + 连接支持服务」更可能归入「主页最终扩展（5%，数字孪生 / 知识库 / 新增功能）」阶段，也就是后面版本再处理。此前的「阶段六：发布与公开访问」为错误合并，现已移除。
>
> 计划把课程要求的 AI 合规日志、Git 历史、用户反馈、过程证据内嵌进对应步骤，避免后补。

## 四、本次对话的关键决策

- **记录机制**：建立 `docs/记录/` 目录，包含 `对话记录/`（每版本一份 md）与 `主页截图/`（每版本全屏截图）。
- **记录规范**：写入 `docs/记录/README.md`，约定命名与结构。
- **对话记录粒度**：每完成一个版本 / 阶段，整理一份该版本的完整对话记录 md（与版本强对应）。
- **截图时机**：仅在完成一个阶段 / 版本后，用全屏截图记录最终样式。
- **截图方式（双重保障）**：
  1. 自动截图（主）：DeepWorks 内置浏览器打开主页本地预览地址，全屏截图自动保存。
  2. 手动截图（辅助）：用户系统全屏截图后放入 `docs/记录/主页截图/`，DeepWorks 负责整理命名。
- **版本命名**：建议 V0（规划）、V1（首个可运行主页）、V2…随迭代递增。
