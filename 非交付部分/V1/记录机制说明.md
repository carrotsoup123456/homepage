# 记录机制说明

本说明用于规范个人主页项目过程中的全部记录，满足课程「过程可追溯」的要求。

## 记录范围

课程要求对过程进行完整记录，包括但不限于：

- 用户与 DeepWorks 的对话内容（决策、需求、方案）
- 页面版本样式截图
- AI 协作过程（单独记录 prompt / 输出 / 修改）
- Git 提交历史（由仓库自身保留）

## 目录结构

```
deepworks项目/
├── 可通用部分/                  # 可给其他 AI/智能体复用的内容（与个人主页同级）
└── 个人主页/
    ├── 交付部分/
    │   ├── md文件/            # 可提交的 md 文件（含对话记录、各版本过程证据）
    │   └── 图片文件夹/        # 每个版本主页的全屏截图
    └── 非交付部分/
        ├── V1/                # 每个版本的内部文件（V2、V3… 同级新建）
        └── ...
```

## 对话记录规则

- 文件名格式：`<版本号>-<会话主题>.md`，例如 `00-项目启动与需求规划.md`。
- **分段粒度：每完成一个版本 / 阶段，整理一份**该版本期间的完整对话记录 md（与版本强对应）。
- 内容结构：会话主题、日期、用户需求、我的方案、关键决策、待办事项。
- 存放位置：`个人主页/交付部分/md文件/`（作为可提交的过程证据）。

## 主页截图规则

- 用**全屏截图**记录每个版本完成后的主页实际样式。
- 命名格式：`<版本号>-首页.png`（多页可加-子页，如 `V1-首页.png`、`V1-项目页.png`）。
- **仅在完成一个阶段 / 版本后截图**，截图前确保页面为最终该版本的样式。
- 存放位置：`个人主页/交付部分/图片文件夹/`，便于评审对比版本演进。
- **截图方式：双重保障**
  1. **自动截图（主）**：DeepWorks 内置浏览器打开主页本地预览地址，用全屏截图自动保存，真实反映渲染效果。
  2. **手动截图（辅助）**：用户本人在浏览器用系统全屏截图（如 Command+Shift+3/4），放入 `交付部分/图片文件夹/`，DeepWorks 负责整理命名与记录。
- 两种截图并存，互为备份；自动截图为主，手动截图用于补充/核对。

## 命名约定

- 版本号建议：V0（规划）、V1（首个可运行主页）、V2、V3…随迭代递增。
- 可通用内容统一放 `可通用部分/`；各版本内部文件放对应 `非交付部分/V<n>/`。
